# 现场部署准备目录

本目录可在填写完成后复制到 Orin 的 `~/stair_site/`，也可保留在仓库内并在启动时传入这里的绝对路径。部署与编译步骤见[主 README](../README.md)。

**当前已接入 `~/map_2d` 的二维地图，路线和地图的现场待确认项仍为空，不能直接启动巡检。** `m20_orin.yaml` 为原厂接口模板副本，保留只读、未确认和仅平地的默认设置。

```text
stair_site/
  route.yaml                  # 已建立 maps/floor_1.yaml 引用，节点和路段待填写
  mission.yaml                # 已引用 route.yaml，执行序列待填写
  m20_orin.yaml                # M20 接口模板
  maps/
    floor_1.yaml              # 已转换的现场二维占据栅格
    map_2d/                   # ~/map_2d 的原始文件副本
      map.yaml
      map.pgm
      map_2d.pcd
    stair_ab.yaml             # 楼梯高度栅格占位
  paths/
    ab.yaml                   # 预设路径占位
```

| 文件 | 当前内容 | 后续需要填写 |
|---|---|---|
| `route.yaml` | 路线结构占位，defaults 已引用现场二维地图 | 坐标系、实测节点、路段、跟踪/规划/到达参数 |
| `mission.yaml` | 任务 ID、相对路线路径、空执行序列 | 与路线一致的段序列及需要调整的任务参数 |
| `m20_orin.yaml` | 项目自带 M20 接口模板 | 实际接口、已验证能力、模式和速度限制 |
| `maps/floor_1.yaml` | 已转换的占据栅格，frame/height_z 为空 | 与定位一致的坐标系、平台支撑高度及实际通行范围确认 |
| `maps/map_2d/` | 原始 YAML、PGM 和 PCD 副本 | 源地图更新后重新同步和转换 |
| `maps/stair_ab.yaml` | 楼梯地图字段占位 | 使用高度栅格规划时的占据与支撑高度 |
| `paths/ab.yaml` | 空预设路径 | 使用独立预设路径文件时的实测路径点 |

按实际后端选择地图或预设路径，不必同时使用全部占位文件。路线的相对地图/路径引用从本目录解析，任务的 `route_file: route.yaml` 也指向本目录。

地图副本来自 `/home/guest/map_2d/`，保留原始文件内容；这是一份快照，不会随源目录自动更新。`floor_1` 仅为项目内部标识，不代表已确认实际楼层。`route.yaml` 的默认地图引用会被各段继承，其他平台和楼梯段需覆盖自己的 `platform_id/grid_file`。

已转换的数据为 326 列 × 232 行，分辨率 0.05 m，XY 原点为 `[-5.297128, -5.562964]`。原始 `origin[2] = 0.0` 是平面旋转角，不作为支撑高度。图像行已上下翻转为项目使用的 `data[y][x]`，占据概率按 `negate: 0` 和源阈值计算：大于 0.65 为 100，小于 0.196 为 0，其余为 -1。结果包含 1,625 个障碍格、74,007 个空闲格、0 个未知格；需现场核对未扫描区域是否被导出为空闲，以及实际可通行范围。

以下内容未从二维地图推断，继续留空：地图和路线的 `frame`、平台 `height_z`、节点坐标及朝向、路段与任务序列、到达容差、障碍膨胀和跟踪参数。原始 PCD 仅归档，不作为当前规划器输入，也未据此生成楼梯高度。填写前，地图加载和路线校验仍会拒绝执行。

建议先填写平地 A→B 的最小路线并完成实机闭环，再增加多段和楼梯。不得将空地图填成全空闲、复制演示坐标或虚报能力来通过预检。

本目录的二维地图不替代原厂定位系统的地图加载和初始化。本目录仍不包含固件匹配的 `drdds` 消息包、支撑参考估计程序及楼梯保持/出梯监督程序。这些仍需按主 README 接入；配置文件不会提供对应运行输入。

M20 模板的 `normal_location_status=-1` 表示未确认，`dry_run=true` 表示只读。完成现场核实后，需按主 README 显式传入定位正常码及实机启动参数；这些 launch 参数会覆盖 YAML 中的同名值。
