# 现场部署准备目录

本目录可在填写完成后复制到 Orin 的 `~/stair_site/`，也可保留在仓库内并在启动时传入这里的绝对路径。部署与编译步骤见[主 README](../README.md)。

**当前用于独立测试 APPROACH_A：从机器人当前有效定位出发，到 A 点并确认保持后结束。** 已接入 `~/map_2d` 的二维地图，并选定 A 点地图坐标 X=2.0 m、Y=0.0 m。支撑高度、A 点朝向及地图坐标系仍需补齐和对齐，已有速度与净空参数需现场复核。`m20_orin.yaml` 为原厂接口模板副本，保留只读、未确认和仅平地的默认设置。

```text
stair_site/
  route.yaml                  # APPROACH_A 单段，已引用地图，A 点及实测参数待填写
  mission.yaml                # 仅执行 APPROACH_A，起点取实时定位
  m20_orin.yaml                # M20 接口模板
  maps/
    floor_1.yaml              # 已转换的现场二维占据栅格
    map_2d/                   # ~/map_2d 的原始文件副本
      map.yaml
      map.pgm
      map_2d.pcd
    stair_ab.yaml             # 楼梯高度栅格占位
  paths/
    ab.yaml                   # 预设路径占位
```

| 文件 | 当前内容 | 后续需要填写 |
|---|---|---|
| `route.yaml` | APPROACH_A 单段，A 点 XY 已填写，已填写跟踪/规划/到达参考值 | A 点 Z 和朝向、坐标系对齐，复核最低有效线速度及障碍膨胀半径 |
| `mission.yaml` | site_approach_a，唯一执行段 APPROACH_A，已填写就绪及超时参考值 | 联调后按实际耗时调整 |
| `m20_orin.yaml` | 项目自带 M20 接口模板 | 实际接口、已验证能力、模式和速度限制 |
| `maps/floor_1.yaml` | 已转换的占据栅格，frame/height_z 为空 | 与定位一致的坐标系、平台支撑高度及实际通行范围确认 |
| `maps/map_2d/` | 原始 YAML、PGM 和 PCD 副本 | 源地图更新后重新同步和转换 |
| `maps/stair_ab.yaml` | 楼梯地图字段占位 | 使用高度栅格规划时的占据与支撑高度 |
| `paths/ab.yaml` | 空预设路径 | 使用独立预设路径文件时的实测路径点 |

按实际后端选择地图或预设路径，不必同时使用全部占位文件。路线的相对地图/路径引用从本目录解析，任务的 `route_file: route.yaml` 也指向本目录。

地图副本来自 `/home/guest/map_2d/`，保留原始文件内容；这是一份快照，不会随源目录自动更新。`floor_1` 仅为项目内部标识，不代表已确认实际楼层。`route.yaml` 的默认地图引用会被各段继承，其他平台和楼梯段需覆盖自己的 `platform_id/grid_file`。

已转换的数据为 326 列 × 232 行，分辨率 0.05 m，XY 原点为 `[-5.297128, -5.562964]`。原始 `origin[2] = 0.0` 是平面旋转角，不作为支撑高度。图像行已上下翻转为项目使用的 `data[y][x]`，占据概率按 `negate: 0` 和源阈值计算：大于 0.65 为 100，小于 0.196 为 0，其余为 -1。结果包含 1,625 个障碍格、74,007 个空闲格、0 个未知格；需现场核对未扫描区域是否被导出为空闲，以及实际可通行范围。

仍需实际确认或复核的字段如下；已填写数值不等同于已完成现场标定：

| 文件 | 字段及当前状态 | 确认依据 |
|---|---|---|
| `route.yaml` | `frame: map`，待与地图和定位核对 | 地图与定位的实际坐标基准 |
| `route.yaml` | `nodes.A.position: [2.0, 0.0, null]`、`nodes.A.yaw: null` | 地图 XY 已选定，支撑参考 Z 和目标朝向待确认 |
| `route.yaml` | `defaults.tracking.min_vx: 0.1`，待复核 | 本机在当前负载下的最低有效前进响应 |
| `route.yaml` | `defaults.planning.inflation_radius: 0.4`，待复核 | 机体/负载尺寸、定位误差和通道净空 |
| `maps/floor_1.yaml` | `frame`、`height_z` | 同一坐标基准下的一层支撑高度 |

`min_vx` 参与减速计算，后续还会经过航向缩放和加速度限制，实际瞬时指令可能更小；适配器只诊断速度死区，不会自动补偿。原始 PCD 仅归档，不作为当前规划器输入，也未据此生成楼梯高度。上述空值补齐前，地图加载和路线校验仍会拒绝执行。

本次路线与任务的 `sequence` 均为 `[APPROACH_A]`，后端为 `platform + grid_astar`，运动模式为 `flat`。段的 `start: A/end: A` 是节点引用，规划器直接以当前定位作为路径起点，不需要填写固定的起始点。任务设置 `readiness.require_start_node: false`，允许从 A 点以外的当前有效位置开始；定位、运控、控制释放、栅格起点合法性、高度、碰撞和连通性检查继续生效。独立测试不设置 `approach_segment`，该字段用于完整任务的前置接近段，不能与唯一执行段重复。

到达 A 点需要同时满足位置、高度、朝向、路径进度及连续保持/稳定确认。原地转向、倒退和楼梯修正目前关闭；若实际目标朝向需要原地转向，需先验证能力，再同时修改路线开关和适配器的能力声明。不得复制演示坐标、将空地图填成全空闲或虚报能力来通过预检。

待 null 参数全部确认、定位接入和只读联调通过，并按主 README 启用适配器、确认控制释放后，可发送一次该最小任务：

```bash
ros2 run stair_nav mission_client --route-id site_approach_a
```

该请求只执行 APPROACH_A。验收为实际到达 A 点、停止并稳定保持、任务返回 `SUCCEEDED`，且导航状态确认控制释放。软件模拟检查不能替代该现场验收。

本目录的二维地图不替代原厂定位系统的地图加载和初始化。本目录仍不包含固件匹配的 `drdds` 消息包、支撑参考估计程序及楼梯保持/出梯监督程序。这些仍需按主 README 接入；配置文件不会提供对应运行输入。

M20 模板的 `normal_location_status=-1` 表示未确认，`dry_run=true` 表示只读。完成现场核实后，需按主 README 显式传入定位正常码及实机启动参数；这些 launch 参数会覆盖 YAML 中的同名值。
